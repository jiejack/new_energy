## 1. 迭代规划概述

### 1.1 规划背景

基于代码审查报告（[05_code_review.md](05_code_review.md)）和需求分析报告（[01_requirements_analysis.md](01_requirements_analysis.md)），NEM 系统当前存在以下突出问题：

| 问题类别 | 严重程度 | 具体表现 |
|----------|----------|----------|
| 关键缺陷 | 🔴 严重 | DryRun 无限循环、6 处 SQL 注入、GORM autoCreateTime 覆盖、删除操作无事务 |
| 性能隐患 | 🟠 高 | checkTaskCancelled 频繁 DB 查询、Redis KEYS 命令、缓存键不稳定 |
| 安全风险 | 🟠 高 | 输入验证缺失、认证 TODO 未完成、敏感信息泄露 |
| 测试不足 | 🟠 高 | 23 个包 0% 覆盖率、persistence 189 个未测函数、knowledge 162 个、rule engine 135 个 |
| 代码质量 | 🟡 中 | 长函数、硬编码值、代码重复（cleanup/archive 60% 重复）、36 处 TODO |
| 架构缺陷 | 🟡 中 | 空实现 Handler、缺少认证中间件、错误处理不一致 |

### 1.2 规划原则

| 原则 | 说明 |
|------|------|
| **安全优先** | 安全漏洞（SQL 注入、认证缺失）优先于功能开发，零容忍高危漏洞上线 |
| **渐进演进** | 先修复 → 再补测 → 后优化 → 最后扩展，每阶段可独立交付 |
| **质量门禁** | 阶段间设置质量门禁，未达标不进入下一阶段 |
| **测试驱动** | 所有修复和新功能必须附带测试用例，覆盖率逐阶段提升 |
| **风险可控** | 每阶段识别关键风险并制定缓解策略，避免大爆炸式集成 |
| **向后兼容** | API 变更保持版本兼容，数据库迁移采用增量脚本 |
