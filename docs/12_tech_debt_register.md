## 1. 技术债务概述

### 1.1 文档目的

本文档系统登记 NEM 项目中存在的技术债务，评估其严重程度与影响范围，制定分阶段偿还计划，并建立预防机制，避免债务持续积累。技术债务管理是保障系统长期可维护性、可演进性的关键工程实践。

### 1.2 技术债务定义

技术债务（Technical Debt）是指在软件开发过程中，为了快速交付短期目标而采取的次优技术方案，所产生的需要在后续工作中偿还的"债务"。若不主动管理，技术债务会持续累积利息，导致开发效率下降、缺陷率上升、维护成本增加。

### 1.3 债务现状概览

### 1.4 债务来源分析

| 来源 | 占比 | 典型案例 |
|------|------|----------|
| 快速交付压力 | 40% | 空实现 Handler、硬编码 |

| 经验不足 | 20% | 错误处理不一致、缺少中间件 |
| 测试不足 | 10% | 低覆盖率、缺陷遗留 |
| 文档缺失 | 5% | 接口文档不全 |

## 4. 偿还计划

### 4.1 偿还原则

1. **安全优先**：安全类债务（DS-01、DS-02）最高优先级，立即偿还
2. **影响驱动**：按影响范围与严重程度排序，高影响优先
3. **分阶段偿还**：结合开发计划，每阶段预留 20% 时间偿还债务
4. **持续偿还**：新功能开发时同步偿还相关债务，避免新增
5. **量化跟踪**：每月统计债务数量，确保趋势下降

## 6. 预防措施

### 6.1 开发流程预防

| 措施 | 描述 | 实施阶段 |
|------|------|----------|
| 代码评审 | 所有 PR 必须至少 1 人评审，关注债务引入 | Phase 2 起 |
| 质量门禁 | CI 强制覆盖率、Lint、安全扫描 | Phase 2 起 |
| 架构评审 | 重大设计变更需架构评审 | Phase 3 起 |
| 技术方案评审 | 复杂功能需先评审技术方案 | Phase 2 起 |
| 还债预留 | 每迭代预留 20% 时间偿还技术债务 | Phase 2 起 |

### 6.2 编码规范预防

| 措施 | 描述 | 工具 |
|------|------|------|
| 代码规范 | 遵循 Go / Vue 官方规范 | golangci-lint / eslint |
| 函数长度 | 函数 ≤ 80 行 | golangci-lint (funlen) |
| 圈复杂度 | 圈复杂度 ≤ 15 | golangci-lint (gocyclo) |
| 参数数量 | 函数参数 ≤ 5 个 | golangci-lint (gocritic) |
| 嵌套深度 | 嵌套 ≤ 4 层 | golangci-lint (nestif) |
| 重复代码 | 重复率 ≤ 5% | jscpd |
| TODO 管理 | TODO 必须关联 Issue | 自定义检查 |

### 6.3 架构预防

| 措施 | 描述 |
|------|------|
| 分层架构 | 严格遵循 Handler → Service → Repository 分层 |
| 依赖注入 | 使用 wire 管理依赖，避免循环依赖 |
| 接口抽象 | 依赖接口而非实现，降低耦合 |
| 领域驱动 | 核心领域使用 DDD 设计，隔离业务逻辑 |
| 配置外置 | 所有配置通过配置中心管理，禁止硬编码 |
| 统一错误处理 | 使用统一错误码与错误处理中间件 |

### 6.4 测试预防

| 措施 | 描述 |
|------|------|
| 测试先行 | 新功能必须同步编写测试 |
| 覆盖率门禁 | 新代码覆盖率 ≥ 80% |
