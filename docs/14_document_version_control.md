## 1. 版本控制概述

### 1.1 目的

本文档定义新能源监控系统（NEM）项目文档的版本控制机制，确保所有项目文档在创建、评审、发布、维护、归档全生命周期内**可追溯、可审计、可维护**。文档版本控制是项目知识资产管理的基石，旨在：

- 保证协作者（含 AI 代理与人类开发者）始终使用最新有效版本。
- 任何文档变更均可追溯至具体版本、变更人与变更原因。
- 避免文档冲突、版本混乱与信息丢失。

### 1.2 适用范围

本机制适用于 `docs/` 目录下的所有文档，包括编号文档（01-15）、非编号主题文档、Wiki 文档及技能文档。

### 1.3 基本原则

| 原则 | 说明 |
|------|------|
| 唯一真相源 | 每份文档在仓库中仅保留一份有效版本，禁止多副本并存 |
| 版本即承诺 | 版本号变更代表内容承诺的变化，需经评审 |
| 变更留痕 | 任何内容修改必须记录于变更记录表，禁止无痕修改 |
| 文档先行 | 编码前先产出文档，文档版本先于代码版本 |

## 3. 版本号规范

### 3.1 语义化版本（SemVer）

NEM 文档采用语义化版本号 `Major.Minor.Patch`（主版本.次版本.修订号），格式为 `vX.Y.Z`：

| 版本段 | 触发条件 | 示例 |
|-------|---------|------|
| Major（主版本） | 文档定位、结构或核心内容发生重大重构；文档合并、拆分或废弃重组 | v1.0.0 → v2.0.0 |
| Minor（次版本） | 新增章节、新增功能模块说明、内容实质性扩充 | v1.0.0 → v1.1.0 |
| Patch（修订号） | 修正错误、补充细节、优化表述、更新日期等小幅修订 | v1.0.0 → v1.0.1 |

### 3.2 版本演进规则

- **初始版本**：文档首次创建为 `v1.0.0`。
- **递增约束**：每次变更仅递增最高受影响位，低位归零。例如 Minor 递增时 Patch 归零。
- **预发布版本**（可选）：评审中未正式发布的版本可标记为 `v1.0.0-rc.1`、`v1.0.0-draft`。
- **版本不可回退**：已发布的版本号不可重复使用，版本号单调递增。

### 3.3 版本号标注位置

每份文档头部"版本信息表"中必须包含 `文档版本` 字段，值为当前语义化版本号，如 `v1.0.0`。

## 4. 变更记录规范

### 4.1 变更记录表

每份文档末尾必须维护"变更记录表"，记录每次版本变更：

| 列名 | 说明 | 示例 |
|------|------|------|
| 版本 | 本次变更后的版本号 | v1.1.0 |
| 日期 | 变更日期（YYYY-MM-DD） | 2026-06-17 |
| 变更内容 | 简明描述本次变更要点 | 新增"文档评审流程"章节 |
| 变更人 | 发起变更的负责人或 AI Agent 标识 | AI Agent / 张三 |

### 4.2 变更记录要求

- **必填**：任何内容修改（含错别字修正）都必须新增一行变更记录。
- **顺序**：按版本时间倒序或正序排列，同一文档内保持一致；推荐新记录追加在表末。
- **粒度**：变更内容描述应聚焦"做了什么"，避免空泛表述如"更新文档"。
- **关联**：重大变更（Major/Minor）应在 `docs/CHANGELOG.md` 中同步登记。

### 4.3 CHANGELOG 汇总

`docs/CHANGELOG.md` 汇总全项目文档变更，按日期倒序组织，每条记录引用具体文档与版本。

## 5. 文档生命周期

### 5.1 生命周期阶段

每份文档经历以下五个阶段：

```
起草（Draft）→ 评审（Review）→ 发布（Published）→ 维护（Maintained）→ 归档（Archived）
```

| 阶段 | 状态标识 | 说明 | 准入条件 |
|------|---------|------|---------|
| 起草 | Draft | 作者编写初稿，内容可频繁变更 | 确定文档目标与大纲 |
| 评审 | Review | 提交评审，收集修改意见 | 初稿完成，结构完整 |
| 发布 | Published | 评审通过，正式生效 | 评审通过，版本号确定为 v1.0.0 |
| 维护 | Maintained | 持续更新，跟进项目演进 | 文档已发布，项目持续迭代 |
| 归档 | Archived | 不再适用，移入归档区 | 文档被替代或废弃 |

### 5.2 阶段转换规则

- **起草 → 评审**：初稿完成且自检通过后，作者主动提交评审。
- **评审 → 发布**：评审意见全部解决，评审人签字确认。
- **发布 → 维护**：发布即进入维护，后续变更走 Minor/Patch 版本。
- **维护 → 归档**：文档被新文档替代时，在原文档顶部标注"已废弃"及替代文档链接，并移入 `docs/wiki/archive/`（如适用）。

### 5.3 废弃处理

- 废弃文档**不得直接删除**，须保留历史记录。
- 在文档头部版本信息表下方添加醒目标注：`> ⚠️ 本文档已废弃，替代文档：[链接]`。
- 在 `docs/CHANGELOG.md` 登记废弃记录。

## 6. 文档评审流程

### 6.1 评审角色

| 角色 | 职责 |
|------|------|
| 作者 | 编写初稿，响应评审意见，完成修改 |
| 评审人 | 审查内容准确性、完整性、规范性，提出修改意见 |
| 技术负责人 | 仲裁评审分歧，确认发布 |

### 6.2 评审流程

```
1. 作者完成初稿 → 自检清单核对
        ↓
2. 提交评审（在 PR / 评审单中指定评审人）
        ↓
3. 评审人审查（对照文档质量标准，第 9 章）
        ↓
4. 提出修改意见 → 作者修订 → 评审人复核
        ↓ （循环直至无阻塞意见）
5. 评审通过 → 技术负责人确认 → 版本号定为 v1.0.0 → 正式发布
```

### 6.3 评审要点

- 内容是否准确反映当前系统现状（非过时信息）。
- 结构是否完整，章节是否覆盖文档定位要求。
- 是否与关联文档保持一致，无矛盾。
- 是否符合版本信息表、变更记录表等格式规范。

## 7. 文档存储与索引

### 7.1 统一存放

所有项目文档统一存放于 `docs/` 目录下，禁止散落在仓库根目录、代码目录或其他位置。临时笔记、草稿放入 `docs/plans/`。

### 7.2 目录索引

- `docs/README.md`：文档目录总说明，维护完整目录树与分类说明表。
- `docs/13_project_wiki.md`：项目知识 Wiki，维护知识库索引（第 10 章）。
- `AGENTS.md`：维护 01-15 编号文档索引表。

### 7.3 链接规范

- 文档间引用使用相对路径，确保本地与 IDE 可点击跳转。
- 引用编号文档使用统一格式：`[13 项目知识 Wiki](13_project_wiki.md)`。
- 外部链接注明来源与访问日期，避免链接腐烂。

## 8. 文档追溯机制

### 8.1 Git 版本追溯

文档与代码同置于 Git 仓库，所有文档变更通过 Git 提交记录追溯：

- 每次文档修改须独立提交，提交信息遵循 Conventional Commits 规范（如 `docs: 新增文档版本控制机制`）。
- 禁止将文档变更与代码变更混入同一提交，保证追溯清晰。

### 8.2 变更记录追溯

- 文档内"变更记录表"记录版本级变更摘要。
- `docs/CHANGELOG.md` 汇总项目级文档变更。
- 二者互补：变更记录表聚焦单文档，CHANGELOG 聚焦全项目。

### 8.3 追溯查询

通过以下方式追溯任意文档的历史版本：
1. Git log 查看文件提交历史：`git log --follow docs/13_project_wiki.md`。
2. 文档内变更记录表查看版本变更摘要。
3. `docs/CHANGELOG.md` 查看项目级变更上下文。

## 9. 文档质量标准

### 9.1 格式标准

- **版本信息表**：文档头部必须包含版本信息表（含文档版本、文档名称、适用项目、最后更新等字段）。
- **变更记录表**：文档末尾必须包含变更记录表。
- **目录**：篇幅较长的文档须包含目录，锚点链接可跳转。
- **Markdown 规范**：使用标准 Markdown 语法，表格对齐，标题层级清晰（不超过四级）。

### 9.2 内容标准

| 维度 | 标准 |
|------|------|
| 准确性 | 内容与系统现状一致，无过时或错误信息 |
| 完整性 | 章节覆盖文档定位要求，无关键缺失 |
| 一致性 | 与关联文档无矛盾，术语统一 |
| 可读性 | 结构清晰，表述简明，新成员可理解 |
| 可操作性 | 流程类文档提供可执行步骤，非空泛描述 |

### 9.3 质量检查清单

- [ ] 文档头部版本信息表完整且字段准确？
- [ ] 文档末尾变更记录表已更新本次变更？
- [ ] 目录锚点链接有效可跳转？
- [ ] 内容反映当前系统现状，无过时信息？
- [ ] 与关联文档交叉引用一致？
- [ ] 无错别字与格式错误？
- [ ] 已在 `docs/CHANGELOG.md` 登记重大变更（如适用）？
